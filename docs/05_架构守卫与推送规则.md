# 05 · 架构守卫与推送规则

> 这份文档里的规则**不是靠人自觉**，而是写进 `scripts/` 由机器强制执行的。
> 任何一条被违反，`bash scripts/check.sh` 就直接红，不给通过。

---

## 一、为什么是"守卫"而不是"文档"

一个人做游戏，最大的架构风险不是设计得不够优雅，而是**半年后自己都忘了当初的约定**。
写在文档里的规范没人会翻；写进脚本、每次自检都跑的规范才算数。

行业里这个做法叫 **ratchet（棘轮）**：

1. 先把规则定成机器可判定的形式；
2. 存量违规登记成"基线"，**只许降不许升**；
3. 新增代码一律按最终标准卡，没有豁免；
4. 重构推进一处，就把对应基线往下调一格，直到清零。

好处是规则**第一天就生效**，不需要先花两周重构历史代码；坏处是一次也偷不了懒。

## 二、三条架构规则（scripts/arch_guard.py）

| 规则 | 内容 | 为什么 |
|---|---|---|
| **R1** | 单个 `.gd` 文件 ≤ 300 行 | 超过 300 行的脚本基本都承担了两种以上职责，改一处容易牵动另一处 |
| **R2** | `core/` 纯逻辑层不得引用任何 autoload | 保证这一层能脱离引擎单测（`godot --script` 模式下 autoload 不注册） |
| **R3** | 不得读写**其他对象**的私有字段（`X._yyy`） | 本项目的头号耦合源：跨模块掀对方盖子，改字段名就崩，且编译期查不出来 |

三条目前**全部零容忍**，没有任何存量豁免（`ALLOW_LINES` / `ALLOW_CORE` / `ALLOW_PRIVATE` 都是空表）。

### 已完成的两次清零（留档，说明这类问题是怎么拆的）

**R1 · HUD.gd 389 行 → 189 行**
拆成"编排器 + 三个哑组件"：

- `ui/HUD/HudTop.gd` —— 顶部信息区（血条 / 波次 / 金币 / 击杀 / 连击 / 暂停按钮）
- `ui/HUD/HudBanners.gd` —— 三条横幅（Boss 波 / 锅气上档 / 解锁提示），共用一套渐隐生命周期
- `ui/HUD/HudButtons.gd` —— 底部按钮（颠勺 / 冲刺），对外只暴露 `toss_rect()` / `dash_rect()`
- `ui/HUD/HUD.gd` —— 只剩"订阅 Events → 分发数据 → 驱动 tick"，不含任何控件构造

每个组件自带 `apply_safe_area()`，安全区平移从"遍历子节点逐个挪 + 重算矩形"简化成"三个容器各挪一次"。

**R3 · 跨模块读私有字段 85 处 → 0**
最大一处是 `EnemySystem` 通过 `game._enemies / _bullets / _rng / _arena / _next_id ...`
直接读写 `Game` 的私有字段 64 处。做法是**抽共享状态对象**：

- 新增 `scenes/BattleWorld.gd`：一场战斗的全部可变状态（对象池 / rng / 竞技场 /
  每帧复用暂存数组 / 颠勺冲击波 / 诊断计数器）。`RefCounted`，不进场景树，可被单测直接 new。
- `Game` 与 `EnemySystem` 各拿同一个实例；`EnemySystem` 里的 `game` 只剩"挂特效节点 + 注册震屏"一个用途。
- 其余：Enemy 加 `wobble() / knockback() / slow_factor()`；Player 加只读访问器
  （`bob_phase() / ifr_left() / dash_state() / radius() / move_dir() / ...`）；
  `Game` 加 `set_player() / is_paused() / step()`；`PickupField` 加公开 `build_pool()`。

### 踩过的坑

- `preload(...).new()` 而不是 `Control.new() + set_script()`：后者静态类型检查会报
  `Function not found in base 'Control'`。
- 别用 `class_name`：`check.sh` 会清 `.godot/editor`，headless 起来时全局类表还没重建，
  会报 `Identifier not declared`。一律用 `const X := preload("res://...")`。
- 守卫的正则必须先剥掉注释与字符串再匹配，否则注释里提到的名字会被误判成真引用。

## 三、两条"跑起来才验得到"的关卡

单元测试跑在 `godot --script` 模式，**那里不注册 autoload**，所以 `Game` / `Player` /
`EnemySystem` 这类真正依赖 `Data` / `Events` / `GameState` 的模块根本没法被单测实例化。
433 个单测全绿，仍可能整条战斗链路是断的。所以补两道关卡：

| 关卡 | 位置 | 验什么 |
|---|---|---|
| 主场景启动 | `check.sh` 1.5 | 清缓存强制重编译后真跑主场景，抓 `Parse Error` / `Identifier not found` |
| 整局集成 | `check.sh` 2.5（`scripts/run_sim.py`） | headless 跑 120 秒模拟，断言刷怪 / 开火 / 命中 / 伤害 / 掉钱 / 波次推进六条链路都有产出 |

`run_sim.py` 已做反向验证：`--sim=1` 时六项全红、退出码 1，确认它真的会拦人而不是摆设。

## 四、推送前自愈规则（scripts/push.sh）

**规则：任何推送都必须走 `bash scripts/push.sh`，不许直接 `git push`。**

原因是沙箱休眠会重置 `/etc/hosts`，`github.com` 的直连 IP 记录随之消失；此时 `git push`
在 TLS 握手阶段失败（`gnutls_handshake() failed`），报错完全看不出是 DNS 问题，
极易误判成"令牌失效"或"没权限"，然后去折腾令牌，越折腾越乱。

`push.sh` 的固定顺序（任一步失败即中止，不做任何推送）：

1. **仓库身份** —— 当前目录必须是 `veggie-arena`，remote 必须是
   `https://github.com/xiaomo945/veggie-arena.git`
2. **全量自检** —— `scripts/check.sh`（语法 / 主场景 / 字体 / 架构守卫 / 433 单测 / 整局集成）
3. **网络自愈** —— 连不上就用 DoH（`dns.alidns.com`）重新解析 `github.com` 与 `api.github.com`，
   写入 `/etc/hosts` **和** `~/.user_hosts`（后者跨沙箱重启保留，避免每次休眠手工修一次）
4. **令牌校验** —— 用真令牌打 `api.github.com/user`，确认身份是 `xiaomo945`（令牌从
   `git credential fill` 取，不硬编码）
5. **推送**
6. **落库校验** —— 比对远端 HEAD 与本地 HEAD，确认真的推上去了（而不只是"没报错"）

```bash
bash scripts/push.sh                  # 检查 + 推送（工作区必须干净）
bash scripts/push.sh -m "提交说明"     # 先提交全部改动，再检查 + 推送
bash scripts/push.sh --no-check       # 跳过全量自检（仅限紧急修补，不推荐）
```

> 顺带一条：中文注释/文案会进字体子集检查（`check.sh` 1.6）。加了新汉字却没重出字体，
> 网页版会显示豆腐块。报错时跑 `python3 scripts/regen_font.py` 再重新导出。

## 五、以后加代码要记住的三句话

1. **先让规则拦住你，再去想要不要破例。** 破例的代价是以后每次都要破例。
2. **长文件不是"以后再拆"，是"现在就该拆"。** 300 行不是审美，是"这个文件已经在做两件事"的信号。
3. **不要为还没出现的需求做抽象。** 出现第二次重复再抽，比提前猜一个抽象更安全。
