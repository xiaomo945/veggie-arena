## 5. 全部公式展开（与 `core/` 真实实现一一对应）

### 5.1 怪物成长（→ `core/Spawner.gd` `stats_for`）
```
hp(w)      = hp_base      + w × hp_per_wave
dmg(w)     = dmg_base     + w × dmg_per_wave
speed(w)   = speed_base   + w × speed_per_wave
精英(elite): hp×2.2, dmg×1.5, gold×3, radius×1.4
Boss: 用 boss 自己的 hp_base/hp_per_wave 等（同公式）
```
当前缩放（落库值，相对初版）：所有非 Boss `hp_per_wave ×0.65`、`dmg_per_wave ×0.58`；`boss.hp_per_wave ×0.70`。
> 守卫：grunt(波20) HP = 14 + 20×8.0535 = **175.1 ≥ 150**（满足测试 #13）。

### 5.2 刷怪预算（→ `core/Spawner.gd` `spawn_rate` / `wave_budget`）
```
spawn_rate(w) = min(cap, base_rate + w × per_wave)     # 线性增长，封顶 cap
wave_budget(w)= spawn_rate(w) × wave.length            # 整波刷出总数
类型概率带    : fast(波2+) / fly(波4+) / swarm(波5+) / brute(波4+) / shambler(波7+)
                + tank(波3+，波6+ 升为 late 概率) + grunt(中段填充)
Boss 波(每5波): 额外 1 只 boss；elite_chance 概率的普通怪变精英
```
当前值：`base_rate=0.28, per_wave=0.24, cap=5.0, elite_chance=0.22`。

### 5.3 武器 DPS 与价格档（→ `core/Combat.gd` `weapon_dps`）
```
DPS = dmg × pellets × (1 + dmg_pct) × (1 + rate_pct) / cd
```
- 价格档（→ `core/Economy.gd` 抽卡权重）：稀有度 `rarity` → 权重 `{1:6, 2:3, 3:1}`；武器权重恒为 `4`。
- 当前 20 把武器：基础 DPS 14.0~59.1（中位 33.5），价格 12~34（中位 22）。
  ⚠️ 见 §7：该表由**武器 Agent** 维护，本文件只给目标区间，禁止在数值侧直接改 `weapons.json`。

### 5.4 合成收益（→ `core/Inventory.gd` `merge_or_add`，真实实现）
```
dmg(lv) = int(round(dmg1 × 1.30^(lv-1)))     # 整数四舍五入
cd(lv)  = cd1  × 0.93^(lv-1)                 # 浮点
单把 DPS(lv) = DPS1 × (1.30 / 0.93)^(lv-1) = DPS1 × 1.3978^(lv-1)
```
| 等级 | 伤害× | 冷却× | DPS× |
|------|------:|------:|------:|
| Lv1 | 1.000 | 1.000 | 1.000 |
| Lv2 | 1.300 | 0.930 | 1.398 |
| Lv3 | 1.690 | 0.865 | 1.954 |
| Lv4 | 2.197 | 0.804 | 2.731 |

> 合成是购买循环的核心正反馈：**每合一级 DPS ≈ +39.8%**，且只花一把武器的钱。
> 这是"最优买"能滚雪球清场、打通 20 波的关键。

### 5.5 道具价值-稀有度档（→ `balance_model.py` `item_value`）
贪心策略按 `价值/价格` 挑最高报价；生存向被显著计价，避免玻璃大炮反而早死：
```
dmg_pct/rate_pct : val×100   crit_chance: val×60   crit_mult: val×40
pellets_add: val×14  pierce_add: val×10   aoe_add: val/9
armor: val×4       max_hp: val×0.6        speed_pct: val×25
gold_pct: val×30   regen: val×3           lifesteal: val×3
dodge: val×40      wok_*: val×15          (其余默认 val×10)
```
> 权重经平衡：纯输出虽高，但 `max_hp/armor/regen` 也显著计分，否则贪心会无视生存早死（实测踩过坑）。

### 5.6 锅气（wok）档位与收益（→ `core/Wok.gd` + `WokEffects.gd`）
```
火候阈值: stir_from=28(翻炒) / wokhei_from=58(爆炒) / ready=100(可投)
tier1(翻炒): 攻速 +tier1_fire = +30%
tier2(爆炒): 攻速 +tier2_fire = +65%  且  伤害 +tier2_dmg = +30%
模型用"清场比例"平滑（避免硬开关导致贪心在清/不清间反复横跳）：
wok_mult(clear_frac) = 1 + ((1+0.65)×(1+0.30) − 1) × clamp(clear_frac,0,1)
                     = 1 + 1.145 × clear_frac      # 全清→2.145×，完全清不掉→1.0×
```
> 颠勺控场（slow/freeze/burn/poison/shred/execute）在模型里折算为最多 25% 的挨打减免。

### 5.7 经济系统（→ `core/Economy.gd`）
```
wave_bonus(w) = bonus_base + w × bonus_per_wave = 14 + 6w
wave_income   = 击杀数 × 平均掉金 × (1+gold_pct) + wave_bonus(w)
波末回血      = max_hp × heal_percent (0.12)
商店: offer_count=4, max_slot=6, max_lv=4, reroll 3+2n
抽卡: 稀有度权重 6/3/1，武器权重 4（武器要凑满 6 槽，不能被 48 道具淹没）
```

### 5.8 玩家生存模型（→ `balance_model.py` `wave_survive`，推演用）
```
capacity  = DPS × 时长 / 平均血           # 这波理论能杀几只
kills     = min(刷出数, capacity)
kill_rate = DPS / 平均血                  # 只/秒
net       = spawn_rate − kill_rate        # 净堆积速率
alive_end = min(net × 时长, MAX_ALIVE=44) # 波末残留封顶
avg_alive = alive_end × 0.5
hps       = min(1/ifr_seconds, avg_alive × CONTACT_K × (1 − skill×0.6))   # 每秒挨打次数
taken     = hps × 时长 × max(min_damage, 平均伤 − armor)
clear_frac= kills / 刷出数
```
> `CONTACT_K = 0.045` 是**全模型唯一需要实机校准的经验参数**（玩家有 0.38s 无敌帧，被摸再密也吃不满封顶）。
> 它是把"零道具 6 波死 / 随机 13 波死 / 最优无限"三个目标钉死的唯一旋钮；若实机偏易/偏难，先调它。

## 6. 武器目标值（⚠️ `weapons.json` 由武器 Agent 维护，数值侧禁止直接改）

本文件**不修改** `weapons.json`。以下仅为写给武器 Agent 的**对齐目标**，确保其改动不破坏 §2/§3 的曲线：

1. **基础 DPS 区间**：单把 Lv1 基础 DPS 建议保持在 **[12, 60]**（当前 14.0~59.1，中位 33.5）。
   越界会直接挪动 §3 的"随机买 13 波死"——DPS 偏高则随机玩家更晚死，偏低则更早死。
2. **价格-强度正相关**：`DPS / cost` 应大致随 `cost`/`rarity` 上升。当前异常点：
   - `fork`（DPS 59.1 / cost 20）强于 `rocket`（DPS 22.2 / cost 34），性价比倒挂。
   - 建议武器 Agent 把 `fork` 下调或 `rocket` 上调，使贵武器确实更强（已通过 `test_economy` 的"火箭筒比手枪贵且 DPS 更高"校验，但跨武器公平性需人工对齐）。
3. **合成后上限**：Lv4 DPS = 基础 × 2.731。若某武器基础 DPS > ~22，合满后单把 > 60，会挤压"最优买滚雪球"的空间，
   使最优玩法过早无敌——请武器 Agent 在加新武器/调数值时，用 `balance_model.py` 复跑确认 §3 结论不变。
4. **引入新武器/改数值后**：必须重跑 `python3 scripts/balance_model.py`，确认三表结论（§2/§3）仍在目标区间；
   若偏移，由本数值侧在 `balance.json` 的 `merge_*` / `spawn` / `wave` / 经济字段反向补偿，**不反改 `weapons.json`**。

## 7. 调参旋钮与结论

**唯一旋钮（经验参数）**：`balance_model.py` 的 `CONTACT_K = 0.045`。实机手感偏易→调大，偏难→调小。

**落库的数值改动（data/*.json）**：
- `balance.json`：`wave.heal_percent 0.10→0.12`、`bonus_base 10→14`、`bonus_per_wave 4→6`；
  `spawn.base_rate 0.5→0.28`、`per_wave 0.26→0.24`、`cap 6.0→5.0`、`elite_chance 0.30→0.22`。
- `enemies.json`：所有非 Boss `hp_per_wave ×0.65`、`dmg_per_wave ×0.58`；`boss.hp_per_wave ×0.70`
  （`speed_*` 未动，保证 §2 的速度不变式）。
- `upgrades.json`：全部 `cost ×0.8`，下限 6（保持进经济循环、不为 0）。
- `weapons.json`：**未改动**（归武器 Agent）。

**一句话结论**：怪物线性成长 + 购买（含合成指数成长）指数成长，二者在 6~35 波平滑交接，
构造出 `零道具 6 波死 → 随机 13 波死 → 最优无限` 的单调难度梯度，且全程满足 7 条不变式；
此后任何数值改动都先在 `balance_model.py` 推演、再回写 JSON，杜绝拍脑袋。
