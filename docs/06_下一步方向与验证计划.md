# 06 · 下一步方向与验证计划

> 决策（2026-10-01）：**先拿真人反馈，再决定往哪堆内容。**
> 本文档是"拿反馈"这条线的施工图。内容深度与 Steam 排在反馈之后。

---

## 一、为什么是这个顺序

一个人 + AI 的真实处境：

- **加内容的边际成本极低** —— 加一把武器、一个强化是几小时的事；
- **但加错方向的成本极高** —— 闷头做两个月，最后发现没人玩；
- **而现在拿反馈的成本几乎为零** —— 网页版已上线、链接可分享、零安装门槛。

结论：**先用最小的代价确认"有人愿意玩、且玩得下去"，再决定把时间砸在哪。**

⚠️ 一件必须点破的事：`docs/04` 阶段 4 写着"这是项目的关键决策点：如果锅气不好玩，
要立刻回到候选 B 或 C"。**这个决策至今没被验证过** —— 现有的证据只有 AI 模拟和
浏览器复现，那只能证明"链路通了"，证明不了"好玩"。

## 二、现状体检（拿反馈之前的拦路虎）

| # | 项 | 现状 | 判定 |
|---|---|---|---|
| 1 | 默认语言 | `I18n.locale = "en"` + 系统语言自动识别 | ✅ 出海没问题 |
| 2 | 首屏玩法说明 | 标题页有英文三行（Drag / Auto-fire / Clear waves） | ✅ |
| 3 | 加载进度条 | `index.html` 带 `fileSizes` 进度 | ✅ |
| 4 | 失败兜底 | 启动失败卡片可关闭（× / 关闭 / 重试）+ 双语报错 | ✅ |
| 5 | **首屏体积** | **47.4 MB（wasm 35.4 + pck 12），服务器零压缩** | ❌ **必修** |
| 6 | **真机验证** | 只在桌面 Chromium 540×960 验过，没碰过真机 | ❌ **必修** |
| 7 | 托管持久性 | 当前是沙箱链接，沙箱不在则链接失效 | ⚠️ 建议换 |

### ❌ 拦路虎 1：首屏 47 MB 无压缩

实测响应头**没有 `content-encoding`**，等于裸传 47 MB。
沙箱带宽 14 MB/s 下 2.5 秒下完，但真机 4G 按 600 KB/s 算 ≈ **80 秒**。
大部分人会在进度条走完之前就关掉 —— 这会直接杀死留存，且**你会误判成"游戏不好玩"**。

解法（按性价比排序）：

| 方案 | 效果 | 代价 | 结论 |
|---|---|---|---|
| **上 itch.io** | 自动 brotli（47 MB → ~15 MB）+ 持久托管 + 自带玩家流量 | 1 小时 | ✅ **推荐，一举三得** |
| 换 Cloudflare Pages / Netlify | 同样自动压缩 | 1 小时，但要自己导流 | 备选 |
| 自建 gzip 静态服务器 | 能压缩，但沙箱一关就死 | 中 | 不推荐 |
| 裁 Godot 模块重编 wasm | 能砍到 ~20 MB | 数小时 + 有弄崩的风险 | **现在别做** |

### ❌ 拦路虎 2：真机没验过

- iOS Safari 的触摸、音频、全屏行为与安卓不同 —— 这是 Godot Web 出海最常见的翻车点。
- 必须**至少一台 iPhone + 一台安卓真机**各跑一局，重点看：摇杆跟手、按钮点得到、
  没有橡皮筋滚动、声音、以及从点开到能玩要多久。

## 三、施工图

### P0 · 让游戏见得了人（约 1 天）

| # | 任务 | 验收 |
|---|---|---|
| P0-1 | 上 itch.io（HTML5 zip 上传），拿持久链接 | 链接在手机浏览器可直接玩；响应头带 `content-encoding` |
| P0-2 | 复测首屏：目标 **< 15 MB 传输、4G 下 < 20 秒** | 用 Chrome DevTools 限速到 Fast 3G / 4G 实测 |
| P0-3 | 一台 iPhone + 一台安卓真机各跑一局 | 摇杆/按钮/声音/全屏全部正常 |
| P0-4 | 首屏加一句体积提示（首次加载约 X MB，之后秒开） | 玩家知道要等，不会以为卡死 |

### P1 · 最轻的埋点（约半天）

原则：**纯本地、不上报、零合规风险**（海外有 GDPR，别给自己找麻烦）。

| # | 任务 | 说明 |
|---|---|---|
| P1-1 | 本地统计：局数、每局到达波次、单局时长、结束原因（阵亡/通关/主动退出） | 存 `SaveMgr`，结算页可看 |
| P1-2 | **一键"复制本局战报"到剪贴板** | 波次 / 击杀 / 时长 / 用了几次颠勺。把潜水党变成评论党，这是性价比最高的一项 |
| P1-3 | 结算页加"分享到评论区"引导 | 直接要反馈，比埋点数字更有用 |

> 为什么强调"复制战报"：这个阶段**定性反馈比定量数据值钱**。
> 你最需要知道的是"哪一步他想关掉"，而不是"平均在线 4 分钟"。

### P2 · 分发（约 1 天）

| 渠道 | 特点 | 优先级 |
|---|---|---|
| **itch.io** | HTML5 游戏主场，有自然流量，零审核 | ⭐ 第一站 |
| Reddit `r/playmygame` | 开发者互相试玩，反馈质量高 | ⭐ |
| Reddit `r/IndieGaming` / `r/incremental_games` | 看题材接受度 | 次 |
| 独立游戏 Discord 服务器 | 能拿到连续几轮反馈 | 次 |
| 小红书 / X 发 15 秒实机短视频 | 竖屏 + 厨房题材天然适合短视频 | 次（顺手） |

发的时候只问三个问题，别问"你觉得怎么样"（没人答得上来）：
1. 玩了几局？第几波关掉的？
2. 有没有注意到"锅气/颠勺"？用上了吗？
3. 哪个瞬间最想关掉？

### P3 · 收口与决策（发完等 3–7 天）

按反馈信号对号入座：

| 反馈信号 | 说明什么 | 下一步 | 成本 |
|---|---|---|---|
| 玩 1 局就走 > 70%，或单局 < 3 分钟 | 钩子没成立 | **回炉核心机制**，别加内容 | 大 |
| 提到最多的是"不知道在干嘛" | 引导问题 | 改教学/首屏说明 | **小** |
| 提到最多的是"太简单 / 太难" | 数值问题 | 只改 `data/*.json` | **小** |
| 没人提"锅气" | 差异化没被感知 | 强化反馈（音效/震屏/UI 提示），或换钩子 | 中 |
| "内容太少、很快就腻" | 内容深度不足 | **这才是加内容的信号** | 大 |

决策树：

```
反馈好（有人玩、有人提锅气、有人问"还有吗"）
  └→ 加内容深度：武器协同/羁绊 → 武器与角色扩容 → 再验一轮 → 上 Steam
反馈中（能玩、但没记忆点）
  └→ 强化差异化：把"厨房/锅气"做成主题系统（多 1–2 个机制）→ 再验一轮
反馈差（没人玩、或玩一局就走）
  └→ 别硬做。核心战斗是成熟的（Brotato 验证过），问题在皮。
      考虑换个题材壳复用核心，或转更小体量的产品
```

## 四、明确不做（现在）

| 不做 | 原因 |
|---|---|
| 继续做架构 | 三条守卫已零容忍、集成安全网已就位。再投入是过度设计 |
| 现在上 Steam | `steam_appid.txt` 还是 0。Steamworks + 成就云存档 + 商店页 + 分级审核是数周量级，且它解决的是"卖"，不是"有人想玩" |
| 原生手游（iOS / 安卓打包） | 另一个量级的坑：证书、商店审核、适配、热更 |
| 联机 / 多人 | 与"验证单人核心是否成立"无关 |
| 裁 wasm 重编引擎 | 收益 ~15 MB，风险高。先靠托管压缩解决 |
| 买量 / 投广告 | 在知道留存之前投钱等于烧钱 |

---

## 五、一句话

**先把 47 MB 砍到 15 MB、把链接挂到 itch.io、找 20 个真人各玩一局。**
这三天能拿到的信息，比再闷头做一个月内容多得多。
