#### 相机黑边缺陷（2026-10-04，修了三次才对）
- **现象**：玩家跑到地图任意边缘（尤其左下角）时镜头仍以玩家为中心、视野越过竞技场边界，屏幕左/下/左下露黑框，可见战斗范围被压成约 1/4；且子弹能飞进黑区击杀"还没露面"的怪。
- **第一次修错**：把 `Camera2D.limit_*` 直接设成竞技场边界。Godot 4.3 的 limit 钳的是**相机中心点**而不是视野 —— 中心点被钳到边界、视野仍探出半屏，黑框照旧。
- **第二次修错（比黑边更糟）**：改成"限位内缩半个视口"（算式对了），但相机仍挂在玩家身上 —— **limit 被当成父节点的局部坐标来解释**，内缩后的区间 `[0,540]×[90,810]` 不含 (0,0)，镜头被钉死在一点，玩家直接跑出屏幕。探针实测：玩家在中心时视野 `(0,90)-(540,900)`，移到左下角后视野纹丝不动，玩家屏幕坐标变成 `(-270,-450)`（完全在屏幕外）。
- **最终修法**：相机从玩家身上摘下来做独立节点，每帧手动钳制 `global_position`。
  - `core/CamLimits.gd`（纯函数、不依赖 autoload，探针和单测可直接测）：`limits(a, view)` 内缩半视口算出"相机中心点允许区间"，任一维出现反转（视口比场地还大）时退化为该维的场地中心；`view_world_size(cam)` 取 `Viewport.get_visible_rect().size ÷ zoom`。
  - `ScreenMode.follow_camera(cam, target, delta)`：钳制目标点后用 `1 - exp(-9 * delta)` 平滑跟随（等效原 `position_smoothing_speed = 9.0`）；每帧重算限位，窗口 resize / 转屏自动适应，无需额外监听。
  - `Main._ready` 建相机后立刻把 `global_position` 设成玩家位置（避免开局从原点飞过来）。
- **探针实测（修后）**：中心 → 视野 `(0,0)-(540,900)`、玩家在屏幕正中 (270,450)，**跟随正常**；左下角 → 视野起点正好落在 `(-270,-360)`、玩家贴屏幕角 (0,0)；右上角 → 视野上边界 1260、玩家贴 (540,900)。四向均不越界 = 无黑框。
- **单测**：`tests/test_cam_limits.gd`（12 条）锁死三类回归 ——「中心不被钳制（跟随生效）」「角落视野不越界（无黑框）」「视口大于场地时限位不反转」。
- **教训（写在这儿防止再犯）**：只验算式（打印限位数值）不算验证，必须验**行为**——从渲染 canvas 变换反算真实视野矩形。沙箱窗口恰好等于设计分辨率 540×900，把坐标系问题完全掩盖住了；`content_scale_size` 恒为 540×900（实测 400×800 窗口下也是），这部分我一开始怀疑错了方向。

### 解锁关系树 + 选角排序（已落地，2026-10-08 夜）

玩家原话："基础角色排序，免费角色要放在最前面，需要解锁的放在后面，或者做一个角色的关系树，
一个角色通关后会解锁哪个角色，那种一看就明白的。" —— 两个都做了，因为它们是同一件事的两面：
**排序解决"我现在能玩谁"，关系树解决"我下一步能拿到谁"。**

**改了什么**
- `core/Unlocks.gd` 新增四个纯函数（全部有单测）：
  - `depth_of`：阶梯深度（free=0，靠别人通关解锁 = 前置 +1）
  - `edges / lanes / standalone`：把规则表翻成"谁解开谁"的车道形状
  - `order`：选角页排序 —— **能玩的一律在前**，组内按"职业线 → 阶梯深浅 → 字母"聚拢
- `ui/Screens/UnlockTree.gd`（新增，274 行，layer 54）：解锁关系树浮层。
  主线 3 列 + 旁路 1 列，节点显示形象/名字/状态，箭头表示"通关上面的就能开下面的"。
  点节点 → 复用 `CharDetail` 详情页（layer 55，正好盖在树上）；点空白处 → 收起。
  底部一条"已拥有 N / 13"进度条 + 一眼可得的完成度。
- `ui/UnlockText.gd`：关系树的双语小词（极短条件式、主线/旁路列名、已拥有/关闭）。
- 标题页右上角新增「UNLOCK MAP / 解锁路线」按钮作为入口。
- `CharacterPicker`：顺序改走 `SaveMgr.character_order()`；解锁事件会现场重排
  （不然新解锁的角色还得在一排灰卡里找，正反馈当场就没了）。

**关键约束**
- **树必须由 `data/unlocks.json` 推导**，不许手抄第二份路线表 —— 加 60 个角色时这张图要自动跟着变。
  单测盯着这一点：车道 + 旁路的并集必须 = 全部角色，且不重不漏。
- 角色变多时整体等比压扁（`MIN_ROW_H` 兜底），不许把节点挤出屏幕。

**踩的坑（写下来防再犯）**
- 自绘屏幕改了数据**必须显式 `queue_redraw`**：Nodes 不会因为数据变了自动重画。
  截图时换完存档，画面还停在上一份存档的"全部已拥有"上，浪费了一轮。
- 旁路列**不能画箭头**：它们之间没有"谁解开谁"，画了就是明目张胆地误导。

## 六、今晚长任务报告：本命武器到底值不值得攒（2026-10-08 凌晨）

> 用户原话："做完这些事就规划新的优化方向，跑今晚的长任务，写进积压任务里，明天见，现在大权交给你。"

### 6.1 先说一件推翻计划的事：原定长任务其实早就做完了

积压里那条 `#211 收窄武器 DPS 离散度（4.9× → 2.2×）`，实测当前已经是 **2.47×**，
闸门 `TARGET_SPREAD = 2.6`。也就是说这条早已达标，再压一遍数值是纯粹的重复劳动。

于是把长任务换成另一个更值钱的问题 —— 而这个 SDK 早就写好了，只是从来没被任何脚本或文档引用过：
`scripts/fullbuild_probe.gd` 算的就是

> `identity = 角色按自己人设能打出的最强 ÷ 随便怎么搭配能打出的最强`

`identity ≈ 1` 表示"照着人设玩就是最优解"，明显小于 1 表示"这个角色的人设只是装饰，照着玩反而更弱"。

这正好就是我上一轮下的那句判断：
> "武器平衡不修的话，玩家顺着阶梯解锁到刀工萝卜，发现还是那两把武器最强，阶梯就白做了。"

### 6.2 结论一：好消息 —— 本命武器确实值得攒

口径：12 波 / 预算 8515 金 / 6 槽（预算每个角色完全一样，差异只能来自角色设计本身）。

| 指标 | 实测 | 判定 |
|---|---|---|
| identity 平均 | **0.98** | ✅ 按人设玩 ≈ 最优解 |
| identity 最低 | 0.90（箭手萝卜 archer） | ✅ 可接受，弓 vs SMG 混合只差 10% |
| identity = 1.00 的角色 | **11 / 13** | ✅ 最优解就是"堆满 6 把本命" |
| 最弱角色通关比 | 1.53（土豆泥 mash） | ✅ 连最弱的也能通关 |

上一轮寂寞地担心的那件事**没有发生**。用户最早那句抱怨
> "武器随便买哪个刷出来就买哪个，反正都没有额外加成"

现在彻底不成立：买武器已经从"比数字大小"重新变成"这把对我有没有用"。
这是今晚唯一一条纯粹的正面结论，也是最该让用户知道的一条。

唯一需要留意的是 `turnip(0.91)` 和 `archer(0.90)` —— 这两个没有被自己的本命完全锁死，
但这是**设计意图**（田园萝卜的人设本来就是"种类要杂"不是"堆同一把"），不是缺陷。

### 6.3 结论二：坏消息 —— 解锁阶梯的强度是倒挂的

跑 `python3 scripts/ladder_report.py` 得到三条主线「深度 → 强度」：

| 线 | 深0 | 深1 | 深2 | 深3 |
|---|---|---|---|---|
| 近战 | turnip 综合 965 | martial **1428** | bruiser 1187 ↓ | mash 1053 ↓ |
| 远程 | archer 494 | commando 383 ↓ | magnet 1063 ↑ | — |
| 法师 | mage 929 | scorch 946 → | — | — |

脚本报出 **6 处告警**，最刺眼的是这一条：

> ⚠ 法师线 mage → scorch：**商店模拟 4.21 → 1.97（掉 53%）**

商店模拟是"真实收入 + 真实购买"的口径，也就是最接近"上手到底好不好打"的一列。
玩家用法师（免费）打得 4.21 倍通关线，通关一次解锁焦辣萝卜，一上手只有 1.97。**腰斩。**

这件事的危害直接打在用户的核心设计上。用户的原话是：
> "基础角色可以免费玩，后面的角色要想玩，需要这个基础角色通关才能玩下一个角色。"

**如果通关换来的角色更弱，解锁就不是奖励而是惩罚**，阶梯就在它自己最关键的那一步失效了：
玩家没有理由再通关第二次，也就没有理由留下来。

### 6.4 为什么不能直接说"给弱角色加伤害"（含一处已更正的误判）

> ⚠ 初稿误判更正：本节原写"EHP 随深度单调递增"，实测**不成立**。
> martial EHP 98 < turnip 118、commando EHP 75 < archer 80 ——
> 这俩是**纯弱**（输出低、生存也低），不是"拿输出换生存"。
> EHP 真正随深度涨的只有 bruiser(183)/mash(250) 这对铁壁，以及 magnet(104)/scorch(145)。

结论因此分两类：

- **martial / commando 型"两头都低"**：综合低是真低，必须实质性提 DPS（commando 靠暴击堆叠；martial 是玻璃刀客、综合已顶全场，属容忍项，见 6.8）。
- **bruiser / mash 型"高 EHP 低 DPS"铁壁**：综合低主要是 DPS 被压太狠，提 DPS 即可，EHP 不动。

报告主判据 **综合 = DPS × EHP**，副判据 **商店模拟**，**两个都不随深度下降才算合格**。
按这个口径，法师线综合没掉（929 → 946），崩的是商店模拟 —— 焦辣萝卜 DoT 人设在真实购买路径里凑不出来，不是数值不够。修法因此是**改羁绊可达性（门槛 6→4）+ 减轻面板惩罚**，不是简单加伤害。

### 6.5 探针的四处口径盲区（写在明处，防止砍错人）

| # | 盲区 | 影响 |
|---|---|---|
| 1 | `flashfire` 的 effect 是 `heat`，模拟器只认 damage / poison / frenzy | 爆炒萝卜技能伤害记 0 |
| 2 | `wok` 用全局常数 1.7，抹掉角色各自的 `wok_pct` | 爆炒萝卜的 0.55 被抹 |
| 3 | `on_hit_dot`（焦辣萝卜每次命中上毒 + 灼烧）模拟器完全没算 | 焦辣萝卜被动输出记 0 |
| 4 | 固定预算口径 | 抹掉囤金者的经济优势，看它请信"商店模拟"列 |

**这四项我都量过**：合计只有 2~4% 的量级，掀翻不了 4.21 vs 1.97 这种两倍的差距。
所以这张排名**可以用**；但必须写在这儿 —— 将来谁据它去砍某个角色，
先确认一下那个角色是不是恰好站在盲区里（爆炒萝卜和焦辣萝卜正是）。

## 七、新的优化方向（2026-10-08 定，距上一版计划过去三天后的重排）

> 排序依据只有一条：**能不能让这个游戏更耐玩**。美术素材按用户吩咐继续往后放。

### P0 · 修解锁阶梯的强度曲线 ✅ 已完成（见 6.8）

- **做什么**：按 `scripts/ladder_report.py` 的告警，让三条主线的强度随解锁深度单调不降。
- **原 6 处告警**：近战线 bruiser / mash 综合倒挂、远程线 commando 综合倒挂、法师线 scorch 商店模拟腰斩、martial 深1 溢出。
- **实际改法**（与初判略有不同，见 6.4 更正）：martial **小削**而非大削（0.2→0.16 rate，综合 1428→1375，给 deep2/3 留空间）；
  bruiser / mash / commando **实质性提 DPS**（mash 原 melee_pct 对远程 blender 无效，改 dmg/ranged 杠杆）；
  scorch **改可达性 + 减面板惩罚**（elemental 门槛 6→4、dmg -0.18→-0.10）。
- **验收**：`--fail-on-inversion` **exit 0**（综合倒挂清零）；check.sh 全绿（见 #233）；导出网页实测。

### P1 · 补完模拟器的技能与锅气口径

- **做什么**：让 `SimChar.skill_parts` 认 `heat`，把 `wok` 从全局常数改成按角色 `wok_pct` 算，
  再把 scorch 的 `on_hit_dot` 接进 `combat_power`。
- **为什么值得做**：这三处现在让两个角色被系统性低估。今天的决策没依赖它（因为差距是大到两倍的），
  但下一次微调时差的可能就在这几个百分点里 —— 那时候口径错误就会真的带偏配平。
- **验收**：新增单测断言三者都被计入；报告里三条盲区删掉并复跑对比。

### P1 · 每波决策密度（用户早已拍板、至今没做）

- 商店节奏改成"每 3 波一次大商店（多卡 + 打折）+ 波间只给 2 张小卡"。
- 单张锁定 / 单张刷新。
- **为什么排在这么前**：用户要的是"耐玩"。现在每一波的决策量太平均，
  这两条能把"每波之间都停下来逛街"变成"攒资源、挑时机"，同时让战斗更连贯 —— 直接作用于爽感。

### P2 · 爽感与流畅度的底层（用户点名"要在底层就做好"）

- 输入缓冲 + 取消窗口（手感跟不跟手的分水岭）。
- 打击反馈分成三档：轻击 / 暴击 / 击杀，各自配不同的震屏、闪光、顿帧。
- 顿帧与震屏做成可关（可访问性）。
- 音频节流：同类音效每帧最多触发一次 + 优先级队列 —— 这是用户最早那条
  "嘟嘟嘟嘟太密了烦死我了"在**底层**的解法，而不是简单地允许用户静音。

### P2 · 三条职业线补齐

- 现在每条线只有 2~4 个角色（近战 4 / 远程 3 / 法师 2），深度不够，阶梯到第三档就断了。
- 先把每条线补到 5 个，正好把 P0 修出来的"强度随深度递增"这条曲线用上去。
- 之前的待办 `#221 E7/E8 新角色`（Warhammer / Repeater / Frostbinder）并入这条。

### P3 · Steam 上架收尾

- `docs/steam_release_checklist.md` 的清单只剩几项非技术项。
- 建议：要么安排一个半天集中清完，要么明确砍掉 —— 挂在积压里既不推进也不取消是最差的。
